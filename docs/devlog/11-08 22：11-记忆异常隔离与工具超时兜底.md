# 记忆异常隔离与工具超时兜底（2026-11-08 22：11）

## 背景

代码评审提出两条：`_execute_tool` 没有超时（工具卡死会卡住整个循环）、`_remember_round` 没有异常处理。
核实后发现第二条的后果与评审描述**相反**，这正是本次修的重点。

## 问题核实

### 记忆：不是"静默失败"，是"整轮打成 500"

评审以为记忆没有异常处理 = 失败感知不到。实际执行顺序是：

```
166  self._publish_reply(...)                    # 回复已推给前端
170  await to_thread(self._remember_round, ...)  # ← 提取器 LLM 调用抛异常
178  session.messages = [...]                    # 永远走不到
```

`MemoryExtractor.extract` 直接调 `self.llm.generate(...)`，真实 DeepSeek 走网络时可能抛
`APIError` / 超时 / 连接错误；`_parse` 只兜住"返回了但 JSON 非法"，兜不住"根本没返回"。
异常一路穿出 `async_run` 的 try（`finally` 只复位 state，不吞异常）→ 500。

后果：**前端已经看到完整回复，接口却返回 500，且这一轮对话没有写回 session，刷新后消失。**
比单纯的 500 更麻烦——用户看到的内容和持久化状态不一致。

`MemoryExtractor` 的 docstring 自己写着"LLM 失败/输出非法时降级为原始 QA，保证记忆写入永远可用
（对齐 Mitta『记忆是优化而非硬依赖』）"——设计意图对，但只实现了"输出非法"那一半。

### 工具：异常兜底其实已有，缺的是超时

`_execute_tool` 早就有 `except TypeError` + `except Exception`，异常会变成 `status="error"` 的
tool_result 回给 LLM，不会冒到循环外。所以评审"会整个崩"的说法不成立。

真正缺的是**超时**：`weather` / `search` 的 `httpx.AsyncClient(timeout=10s)` 覆盖了
connect/read/pool，但 Agent 层没有兜底总超时——工具实现自身出问题（非 httpx 路径）就会一直挂着。

## 改动

| 位置 | 改动 |
| --- | --- |
| `constants.py` | 新增 `TOOL_TIMEOUT_SECONDS = 10.0` |
| `runtime._execute_tool` | `asyncio.wait_for(tool.handler(**args), timeout=TOOL_TIMEOUT_SECONDS)`；`except asyncio.TimeoutError` → `错误：工具执行超时（超过 10s）` + `status="error"` |
| `runtime._build_messages` | `memory.recall` 包 try，失败记 warning 并按"无记忆"继续 |
| `runtime._remember_round` | 三段降级：召回失败 → `existing=[]`；提取失败 → `facts=[qa]`（原始 QA）；写入逐条走 `_remember_safely` |
| `runtime._remember_safely` | 新增，单条写入 try，失败只记日志 |
| `runtime.async_run` | `await to_thread(_remember_round, ...)` 外层再包 try/except，只记 warning |

外层 + 内层双保险：内层按环节降级（尽量把记忆存下来），外层兜住任何漏网异常（保证绝不阻断主流程）。

## 关键取舍

- **记忆是弱一致性的附属功能**：写入失败不该影响回复返回，所以兜住并降级，而不是让它打穿整轮。
- **`wait_for` 的边界**：只对真 await 的工具有效。`calculator` 是包在 `async def` 里的纯 CPU 计算，
  没有 await 点，`wait_for` 取消不了它，只能靠它自身的输入校验与 AST 白名单。这一点不能含糊。
- **没有上 `asyncio.gather`（并行工具调用）**：当前串行执行，工具间无依赖技术上可并行，但收益有限
  （一轮多工具调用本就少，4 个工具里只有 weather/search 能并发），代价是异常隔离、事件顺序、
  `todo` 模块级内存表的竞态。保留为"知道但暂不动"的可选优化点。

## 验证

新增 3 个用例：

- `test_extractor_failure_degrades_to_raw_qa`：提取器抛 `RuntimeError` → 回复正常返回、`session.messages` 已写回、
  记忆降级存原始 QA（覆盖"500 + 历史丢失"的回归）
- `test_memory_recall_failure_does_not_break_round`：`recall` 抛异常（`_build_messages` 与 `_remember_round` 两处调用）→ 整轮正常
- `test_execute_tool_timeout_returns_error`：注册一个 `sleep(10)` 的假工具，把超时 patch 到 0.05s → `status="error"`、文案含"超时"、`duration_ms < 1000`

全量：`175 passed, 1 warning in 7.63s`（172 基线 + 3），告警仍是 pytest 清理 venv 临时目录的历史 WinError 145。
