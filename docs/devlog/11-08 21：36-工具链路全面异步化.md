# 工具链路全面异步化（2026-11-08 21：36）

## 背景

Mitta 之后，agent-harness 的工具执行一直沿用「同步工具 + `asyncio.to_thread` 丢线程池」的做法。
用户指出：涉及 IO 的操作本来就应该是 async，`to_thread` 只是在为同步实现打补丁，链路并没有真正 async。
本次把四个工具全部改 async，并去掉工具执行处的 `to_thread`。

## 改动点

| 文件 | 改动 |
| --- | --- |
| `src/agent/tools/base.py` | `Tool.handler` 类型 `Callable[..., str]` → `Callable[..., Awaitable[str]]` |
| `src/agent/tools/calculator.py` | `run` → `async def run`（纯计算，无 await 点，仅为签名统一） |
| `src/agent/tools/todo.py` | `run` → `async def run`（内存表操作，同样无 await） |
| `src/agent/tools/weather.py` | `_fetch` → `async def`，内部 `httpx.AsyncClient` + `await client.get`；`run` → `async def`，`cond = await _fetch(name)` |
| `src/agent/tools/search.py` | 同上（`_fetch` / `run` 改 async），UA 头随 `client.get` 传 |
| `src/agent/runtime.py` | `_execute_tool` → `@staticmethod async def`，内部 `str(await tool.handler(**args))`；`async_run` 调用点去掉 `asyncio.to_thread` |
| `src/agent/runtime.py` | 同步 `run()` 改为薄包装 `return asyncio.run(self.async_run(...))`，删除原 110 行同步主循环 |

## 关键设计决定：同步 run 保留为薄包装

工具变 async 后，同步主循环没有可 await 的环境，两条路：

1. 同步循环里对每次工具调用 `asyncio.run(...)` —— 一轮多次工具就反复建事件循环，且两套主循环长期并存；
2. 干脆让 `run()` 复用 `async_run()` —— 一份主循环，`run` 只在没有事件循环的同步上下文（测试、脚本）里起循环。

选 2。代价是 `run()` 语义从「同步 LLM 调用」变成「跑一遍异步主循环」，但 `run` 只服务测试与脚本，行为等价（测试全绿）。
约束：`run()` 不能在已有事件循环里调用（会 RuntimeError），App 侧走 `async_run`，不受影响。

## 踩坑：改完一次跑出 21 个失败

全量 `172 passed` → `21 failed`，根因都是「测试仍用同步方式驱动 async 工具」，分三类：

1. **直接同步调用 async 函数**（`test_todo.py` 全部 10 例、`test_tools_network.py` 4 例）
   → 拿到 coroutine 对象，`in` 比较报 `TypeError: argument of type 'coroutine' is not iterable`。
2. **monkeypatch 把 `_fetch` 换回同步 lambda**（`test_tools.py` 2 例、`test_tools_network.py` 4 例）
   → `await` 一个普通返回值/None，报 `object NoneType can't be used in 'await' expression`。
3. **Fake LLM 只伪造了同步 client**（`test_deepseek_llm.py::test_runtime_tool_call_id_matching`）
   → `run()` 走 `async_run` 后调用 `async_generate`，实例上没有 → `AttributeError`。

### 修法

- 不引入 `pytest-asyncio`（`.venv` 与 `requirements.txt` 均无此依赖），继续「同步测试 + `asyncio.run`」路线。
- `test_tools.py` / `test_todo.py` / `test_tools_network.py` 各加一个 `_run(...)` 辅助，把调用统一包一层。
- 所有 monkeypatch 的 `_fetch` 桩改为 `async def` 局部函数（`conftest.py` 的全局桩同样改 async）。
- `test_deepseek_llm.py` 的 `_make_llm` 实例上挂一个 `async_generate`，内部复用同步 `generate`，让协议解析仍走真实代码路径。

结果：`172 passed, 1 warning in 7.76s`（告警仍是 pytest 清理 `.venv/Lib/pip-tmp` 的历史 WinError 145，与本次无关）。
