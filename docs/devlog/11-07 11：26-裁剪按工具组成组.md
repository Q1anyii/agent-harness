# 裁剪按工具组成组

## 问题
`trim_messages` 按条裁剪（从最新往回、超预算 break），切点可能落在工具链中间：

- 保留 `role:"tool"` 结果但丢掉前面的 `assistant(tool_calls)` → 孤立 tool 消息，
  发给 OpenAI 兼容 API 直接 400（tool 消息必须跟随带 tool_calls 的 assistant）；
- 或反向：保留 `assistant(tool_calls)` 但丢掉 tool 结果 → 模型看到"调用了没结果"。

另外 token 估算只算 `content`：assistant 发起工具调用时 content 为空，整轮被估成
0~1 token，而 `tool_calls` 的 name / arguments JSON（搜索词、todo 内容）完全没计入，
导致组成本被低估。

## 方案
- 新增 `message_cost`：content + 每个 tool_call 的 function.name / arguments。
- 新增 `group_messages`：`assistant(tool_calls)` + 紧随的连续 tool 消息为一组，
  其余消息各自成组。
- `trim_messages` 改为按组裁剪：整组保留或整组丢弃；system 与最新一组无条件保留。
- 裁剪时机不变（run 前一次）：历史里的工具链已全部配对完整（`session.messages`
  只在 run 末尾写回，异常不回写），因此不会出现"进行中"的组。

## 验证
- 新增 `test_trim_keeps_tool_group_atomic`：预算卡在工具组中间时整组丢弃，
  输出中无孤立 tool 消息。
- 新增 `test_trim_counts_tool_arguments`：arguments 长时整组被裁、短时保留。
- 全量：172 passed（原 170 + 2）。
