# 全局异常中间件与耗时日志入库（P1 ⑤）

## 背景

P0（①存储抽象+SQLite、③system_prompt+context、②trace嵌入消息、④流式输出、⑥reasoning）已全部完成。P1 ⑤ 要解决：

- 请求耗时不可见：每次对话/工具调用耗了多少，没有统一记录；
- 未捕获异常裸奔：一旦 runtime 或工具抛未预期异常，FastAPI 默认返回 500 纯文本（不 JSON），且前端拿不到统一错误结构；
- 日志没有落库：排查问题只能看终端输出，无法按会话回溯历史请求。

## 设计

### 1. 存储抽象：`src/agent/log.py`（与 SessionStore 同风格）

- `LogRecord`：一条请求日志 = ts/method/path/session_id/status/duration_ms/error；
- `LogStore`（ABC）：`append` + `list`，实现可换（内存 / SQLite / 未来 PG/Redis），中间件只依赖抽象；
- `MemoryLogStore`：测试/演示默认，`list` 最新在前；
- `SQLiteLogStore`：logs 表（id/ts/method/path/session_id/status/duration_ms/error），与会话共用同一 db 文件。

### 2. SQLite 连接根因只写一次：`session.py` 提取公共函数

`SQLiteSessionStore` 里的两个沙箱根因修复（`journal_mode=MEMORY` 绕过 journal 文件拦截、短连接 commit/rollback/close 防 Windows 文件句柄占用）提升为模块级：

- `connect_sqlite(db_path)`：新连接 + MEMORY journal；
- `sqlite_transaction(db_path)`：短连接事务上下文。

`SQLiteSessionStore` 改为薄转发，`SQLiteLogStore` 直接复用——根因注释只保留一份，后续换 PG 只需改这两处。

### 3. 中间件：`src/main.py` 的 `timing_and_error_middleware`

一个中间件完成三件事（请求生命周期内一次写完日志）：

```
正常路径：call_next 返回响应 → 记录 status/duration_ms
异常路径：捕获未捕获异常 → 生成 500 JSON（detail 只给异常类型，不泄露堆栈）→ 记录 error
finally ：统一 append 到 log_store
```

关键语义：

- `HTTPException`（404/409 等业务错误）由内层 `ExceptionMiddleware` 转成响应，**不会**冒泡到本中间件的 except 分支，只被计时记录——业务错误和未预期异常天然分流；
- `session_id` 从路径 `/api/sessions/{sid}/...` 提取为独立列，可按会话回溯某次对话的全部请求耗时与错误；
- `LOG_STORE` 环境变量独立于 `SESSION_STORE` 切换存储（默认 memory，测试稳定）。

## 验证

- 新增 `tests/test_log.py` 7 用例：内存/SQLite 双实现、落库重启读回、LIMIT 倒序、路径提取、正常请求记录、404 记录、未捕获异常兜底（monkeypatch runtime.async_run 抛 RuntimeError → 断言 500 JSON + 日志含 error）；
- 全量测试 156 passed（149 + 7），无回归。
