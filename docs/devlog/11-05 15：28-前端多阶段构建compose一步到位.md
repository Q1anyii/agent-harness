# 部署升级：前端多阶段构建，compose 一步到位（P2 ⑧ 补充）

## 背景

15：09 的 Docker 方案是「宿主构建 dist + compose 挂载」：前置 `cd frontend && npm install && npm run build` 才能 `docker compose up`。

## 设计：多阶段构建（frontend/Dockerfile）

```
stage1  node:20-alpine   COPY frontend/package*.json → npm ci → COPY frontend/ → npm run build → /app/dist
stage2  nginx:1.27-alpine  COPY --from=frontend-build /app/dist → /usr/share/nginx/html
                            COPY deploy/nginx/nginx.conf → /etc/nginx/conf.d/default.conf
```

- **context = 项目根**：compose 中 `nginx.build.context: .` + `dockerfile: frontend/Dockerfile`，Dockerfile 内 COPY 以根为基准（`COPY frontend/...`）——`../` 越出 context 非法，这是初始写法踩的坑；
- **npm ci**：有 package-lock.json，确定性安装；`NPM_REGISTRY` build-arg 支持国内源加速（对齐 Mitta）；
- **镜像自包含**：nginx 镜像自带 dist + 反代配置，compose 去掉挂载 volumes，nginx 服务从 `image:` 改为 `build:`；
- **.dockerignore 联动修正**：
  - `frontend/` 整体排除移除（源码要进构建上下文），保留 `frontend/node_modules|dist|.vite` 排除；
  - `deploy/` 排除移除（nginx.conf 要从 context COPY 进镜像，不再是挂载）。

## 效果

```powershell
cd agent-harness
docker compose up -d --build   # 唯一一条命令；宿主只需 Docker
```

最终产物两个镜像：`api`（python 后端）+ `nginx`（前端多阶段自包含）。构建产物只存中间层，最终镜像不含 node/源码，体积小。

## 验证

- `docker-compose.yml` YAML 校验通过：nginx `build.context=.` + `dockerfile=frontend/Dockerfile`，无 volumes；
- 前端结构核对：src/index.html/tsconfig/vite.config.ts/package-lock.json 齐全，`COPY frontend/ ./` 可完整构建；
- 全量测试 **170 passed**（纯部署层改动，无代码路径影响）；
- 诚实边界：本机无 docker，未真跑构建——Dockerfile 阶段逻辑与 COPY 路径人工核验（含 context 越界坑位修正）。
