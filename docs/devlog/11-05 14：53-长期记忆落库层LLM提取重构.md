# 长期记忆：落库层 LLM 提取重构（对齐 mem0/Mitta 写入管线）

## 背景

⑦ 初版（f6c4304）的落库是"每轮 QA 直接存一条"（`Q: ...\nA: ...` 合并成一条记忆）。用户反馈：**落库层没有经过 LLM 合并**，虽然召回时带上了上下文，但**指代无法覆盖**——如"那南昌呢"承接上文"北京天气"，直接存原始 QA 会存成残缺的孤立片段（`那南昌呢` 单独无法检索/理解）。

用户提供 mem0 深度笔记（MEM0_DEEP_DIVE.md）与 Mitta 源码（memory_service.py / memory_node.py）。读完对齐：

- **Mitta 写路径**：`memory_node` 把本轮 `[user, assistant]` 提交 `memory_service.add` → mem0 内部 **LLM 事实提取 + 入库**（fire-and-forget 后台线程）；
- **mem0 提取 prompt**（`configs/prompts.py`）：`ADDITIVE_EXTRACTION_PROMPT`（Memory Extractor 角色、只做 ADD、提取 BOTH user/assistant、self-contained 事实、不提取无关内容）+ `generate_additive_extraction_prompt` 段落结构 = **Summary / Last k Messages / Recently Extracted Memories / Existing Memories / New Messages / 日期**（+ `use_input_language` 强制原文语言，修 DeepSeek 把中文事实翻译成英文的 bug）；
- **指代消解机制**：提取 prompt 里给「最近 k 条消息 + 已有记忆 + 本轮 QA」，LLM 提取时产出自包含事实——**上下文在提取阶段就被补全**，而非存完再靠召回拼。

## 设计

### 1. `src/agent/memory.py`

- **`build_extract_prompt(existing, new_qa, recent_messages)`**：构造提取 prompt，段落 = `## Existing Memories` / `## Last k Messages` / `## New Messages`（对齐 mem0 结构，简化为本项目三段落）；
- **`EXTRACTOR_SYSTEM_PROMPT`**：提取器角色 + 自包含要求 + 指代补全 + 原文语言 + 判重 + 只输出 `{"facts": [...]}` JSON；首行含「长期记忆提取器」标记，MockLLM 靠它识别提取任务；
- **`MemoryExtractor`**（`recent_k=10`，对齐 mem0 P0 最近 10 条）：
  - `extract(existing, new_qa, recent_messages)` → 事实列表（system=提取器 prompt + user=提取 prompt）；
  - `_parse` 容错：剥 ```json 围栏 → `json.loads` → `{"facts": [...]}`；解析失败/空结果**降级返回 `[fallback_qa]`**（记忆写入永远可用，对齐 Mitta「记忆是优化而非硬依赖」）；
- **`BM25Memory.remember` 加 md5 去重**（对齐 mem0 P4/P5）：与该会话已有记忆 `md5(content)` 完全重复则跳过，不重复入库。

### 2. `src/agent/llm.py`（MockLLM 提取分支）

- `generate` / `async_generate` 开头新增：system 含「长期记忆提取器」→ 走 `_extract_memories` 规则分支，**置于工具路由之前**（提取 prompt 里可能含"天气/计算"触发词，不能误路由工具）；
- `_extract_memories(user_text)`：按段落标记切分（`_slice`）解析 `## Existing/Last k/New Messages` 与 Q:/A:；
  - 问句含指代词（`_REFERENTIAL = 那/这个/这/它/他/她/其/它们`）且最近消息非空 → 用最近消息首行补全主题：`f"{topic}；{answer}"`（"那南昌呢" → "Q: 北京天气如何；南昌多云 20 度"）；
  - 否则取 answer 作为事实；
  - 输出 `{"facts": [...]}`，与真实 LLM 同格式（提取器解析路径一致）。

### 3. `src/agent/runtime.py` 写入管线（5b 处改造）

- `__init__` 新增 `memory_extractor`（默认 None，不配即保持"直接存原始 QA"，既有测试零影响）；
- 新增 `_remember_round(session, user_content, reply)`，写入管线对齐 mem0 §1：
  - **P1 已有记忆**：以本轮提问 `recall(k=5)` 召回相关记忆，供提取器判重/合并参考（防幻觉）；
  - **P0 最近消息**：`session.messages[-recent_k:]` 进提取上下文，消解指代；
  - **P2 LLM 提取**：`extractor.extract(...)` → 事实列表；
  - **P4/P5 去重**：逐条 `remember`（内部 md5 去重）；
- `run`（同步路径）直接调用；**`async_run` 经 `asyncio.to_thread` 包装**——LLM 提取调用不阻塞事件循环（延续 async 异步改造的纪律：IO 密集走线程池/事件循环外执行）。

### 4. `src/main.py`

- LLM 实例先创建（Mock/DeepSeek 按 `LLM_BACKEND` 分支），再 `MemoryExtractor(llm)` 装配进 runtime——提取器与主链路复用同一 LLM，测试必须显式 `LLM_BACKEND=mock`（否则误走真实 DeepSeek）。

## 验证

- 新增 `tests/test_memory.py` 6 用例：无指代提取 = 回复内容；指代消解（"那南昌呢"+最近"北京天气" → 事实含上下文、不含孤立"那"）；非法 JSON 降级；md5 去重；sync 集成（落库为提取后事实、不带 `Q:` 壳）；async 集成（to_thread 路径）；
- 全量测试 **170 passed**（164 基线 + 6），无回归。

## 后续

- 记忆存储落 SQLite（复用 `connect_sqlite`/`sqlite_transaction`，加 memories 表）——当前内存实现足以支撑本地开发，`MemoryStrategy` 接口已预留；
- 提取调用是每轮一次额外 LLM 请求：Mitta 是 fire-and-forget 后台线程，本项目当前同步提取（本地规模可接受），接入 MCP/多 Agent 时可改为线程池提交；
- 已有记忆的显式合并（MEMORY_UPDATE）属 mem0 平台版能力，OSS 为 ADD-only——当前提取自包含事实已覆盖指代，实现口径与 mem0 OSS 一致。
