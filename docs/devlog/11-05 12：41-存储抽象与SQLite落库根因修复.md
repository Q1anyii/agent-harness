# 存储抽象与 SQLite 落库：沙箱拦截 journal 文件根因修复 + system_prompt/context 集成

**日期**：2026-11-05 12:41
**提交**：b5bd368 之后（P0 ①存储抽象+SQLite、③system_prompt+context）

## 一、做了什么

1. **存储抽象（①）**：`src/agent/session.py` 重写为三层——
   - `SessionStore(ABC)`：create / get / list / remove / save 五个抽象方法（Repository 模式）
   - `SessionManager`：内存实现（save 为 no-op，保持既有测试兼容）
   - `SQLiteSessionStore`：sessions / messages / traces 三表落库，标准 SQL（参数化 `?`、UPDATE→INSERT 两步 upsert，不用 SQLite 专有 `INSERT OR REPLACE`，未来换 PG 只换驱动）
   - `main.py` 支持 `SESSION_STORE=memory|sqlite` 环境变量切换（默认 memory，测试稳定；sqlite 默认落 `data/agent-harness.db`，`SESSION_DB` 可覆盖）；`send_message` 在 `async_run` 后调 `manager.save(s)` 落库
2. **context 策略（③）**：新建 `src/agent/context.py`——
   - `estimate_tokens`：无分词器粗算（CJK≈1字1token、英文≈4字符1token，len//2 折中偏保守）
   - `build_system_prompt`：角色 + 可用工具列表 + 工具使用约定 + 当前时间（LLM 无内置时钟）
   - `trim_messages`：context 窗口裁剪——system 无条件保留 + 最后一条 user（当前问题）无条件保留 + 从最新往回保留直到不超窗
   - `runtime.py` 新增 `_build_messages`：system prompt 首次构造存 `session.system_prompt` 后复用、插入消息首条、追加 user、trim 裁剪；sync/async 双路径接入；写回 `session.messages` 时过滤 system（对话历史保持干净，system 只存字段）

## 二、现象

## 三、根因链（重点）

### 根因 1：沙箱拦截 SQLite rollback journal 文件 → DDL/DML 静默失效

最小复现逐步排除：
- 单条 `conn.execute("CREATE TABLE ...")` + `commit()` 也无效 → 不是 `executescript` 的问题
- 普通文本文件写入正常（13 字节持久）→ 不是整个文件写入被拦
- `:memory:` 内存库完全正常 → sqlite3 模块本身可用
- **文件库 + `PRAGMA journal_mode=MEMORY` 完全正常**（close 后文件 8192 字节持久）→ 定位到 **journal 文件**

机制：SQLite 默认 journal_mode=delete，事务依赖创建/写入/删除 `.db-journal` 回滚日志文件；当前运行环境（沙箱）拦截该文件操作，导致事务无法真正提交。表现是 `total_changes=0`、同连接查表为空、**close 后数据库文件变 0 字节**（全部写入被丢弃）。

修复：`_connect()` 里执行 `PRAGMA journal_mode=MEMORY`（事务日志放内存），数据库主文件本身仍正常持久化（实测验证）。崩溃安全性略降（最后未同步事务可能丢失），对单机本地部署可接受。

### 根因 2：`with sqlite3.connect() as conn` 只 commit 不 close → 文件句柄未释放

端到端验证（E2E：落库 → 重启重读 → 列表 → 删除）最后 `os.remove(db)` 报 `PermissionError: [WinError 32]`——连接一直未关闭，Windows 文件句柄占用。

修复：新增 `_session()` 上下文管理器（成功 commit / 异常 rollback / finally 必 close），所有方法改用 `with self._session() as conn:`。

### 根因 3：重写 session.py 时漏掉 `SessionManager.append_trace`

既有 `test_session.py` 调用 `mgr.append_trace(s, traces)`（内存 extend 语义），重写时被删。补回 `SessionManager.append_trace`。

### 根因 4：system prompt 注入打破既有测试的固定索引断言

runtime 现在把 system 消息插到消息首条，`test_deepseek_llm.py` 对发送列表 `sent[1]/sent[2]` 的固定索引假设失效。system 注入是需求行为，测试适配为按角色语义定位（`next(m for m in sent if ...)`），与 `test_runtime.py` 既有风格一致。
