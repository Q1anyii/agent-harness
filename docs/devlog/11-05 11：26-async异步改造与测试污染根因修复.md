# async 异步改造：LLM async_generate + AgentRuntime.async_run + 测试污染根因修复

## 背景

流式输出（明日主题）的前置准备：让 FastAPI 能以异步方式跑 Agent。
改动范围：`LLMClient` 抽象层新增 `async_generate`，`DeepSeekLLM`/`MockLLM` 各自实现，
`AgentRuntime` 新增 `async_run`，`main.py` 路由改为 `async def + await`。
保持 sync 路径（`run()`/`generate()`）不动——120 个既有测试全走 sync，新旧并存最小破坏。

## 现象

async 改造后全量测试 `9 failed / 111 passed`，分三类：

1. 7 个 `test_api.py`：`AttributeError: 'coroutine' object has no attribute 'reply'`
   ——`main.py` 的 `send_message` 调 `runtime.async_run(...)` 未 `await`，拿到的是协程对象；
2. 2 个 TypeError：`NoIdLLM`（test_deepseek_llm.py）/ `MultiToolLLM`（test_runtime.py）
   继承 `LLMClient` 但未实现新抽象方法 `async_generate`，实例化直接失败；
3. 修复前两类后再次全量：`3 failed / 117 passed`，错误变为
   `RuntimeError: Event loop is closed`（ProactorEventLoop closed=True）。

## 根因

1. **sync 函数里不能 await**：`send_message` 仍是 `def`（sync），FastAPI 把它扔进线程池执行，
   函数体里的 `async_run` 返回 coroutine 对象而非结果，访问 `.reply` 必然崩。
2. **抽象契约全局生效**：基类新增 `@abstractmethod async_generate` 后，所有子类必须实现，
   测试辅助类没有跟上。
3. **测试污染（核心根因）**：`.env` 里配置了 `LLM_BACKEND=deepseek`（真实联调时加入），
   `llm.py` 模块顶部 `load_dotenv(override=True)` 用 .env 值**覆盖** shell 显式设置的
   `$env:LLM_BACKEND="mock"` → `runtime.llm` 变成 `DeepSeekLLM` → 测试真的发了
   DeepSeek 网络请求 → `AsyncOpenAI` 的 async client 在 TestClient 的事件循环上发请求，
   响应关闭阶段（`_response_closed → aclose → transport.abort → loop.call_soon`）赶上
   事件循环已关闭 → `Event loop is closed`。测试被真实网络污染，是确定性测试的大忌。

## 修复

1. `src/main.py`：`send_message` 改为 `async def`，`result = await runtime.async_run(s, req.content)`。
   FastAPI 原生支持 async 路由，TestClient 调用方式不变。
2. 测试辅助类补抽象实现（纯 sync 逻辑，直接复用 generate）：
   - `tests/test_deepseek_llm.py::NoIdLLM`：`async def async_generate(self, messages): return self.generate(messages)`
   - `tests/test_runtime.py::MultiToolLLM`：同上
3. `src/agent/llm.py`：`load_dotenv(override=True)` → `load_dotenv()`（默认不覆盖）。
   语义修正为 **shell 显式环境变量优先、.env 兜底**（12-factor 惯例），
   测试命令的 `mock` 不再被 .env 的 `deepseek` 覆盖。
4. 顺手清理：`DeepSeekLLM.__init__` 删除 `if_async` 死参数（init() 已改为双 client 同时创建，不再使用）。

## async 改造内容速览

- `LLMClient(ABC)` 新增 `@abstractmethod async_generate`；
- `DeepSeekLLM.init()` 同时创建 `OpenAI`（sync）与 `AsyncOpenAI`（async）双 client；
  `async_generate` 走 `await self.async_client.chat.completions.create(...)`（AsyncOpenAI 没有 `.async_create`，create 本身即 async）；
- `MockLLM.async_generate` 与 sync 版逻辑一致（纯规则计算，无 IO）；
- `AgentRuntime.async_run` 与 `run` 结构对齐：`await self.llm.async_generate(...)`，
  工具执行包 `await asyncio.to_thread(self._execute_tool, ...)`——
  工具是 sync 阻塞（weather/search 网络调用），直接同步调会卡死事件循环，扔线程池保循环畅通；
  for-else 轮次上限、SessionBusyError、trace、rounds_used 语义与 sync 版完全一致。

## 验证

- 全量：`120 passed`（LLM_BACKEND=mock），耗时从 ~29s 降至 ~8.4s
  （耗时骤降佐证此前测试确实误走真实 DeepSeek 网络请求）。
- sync 路径（120 个既有测试）与 async 路径并存，均可用。

## 遗留

- async 路径已接入 FastAPI，但异步工具执行仍是 `to_thread`（线程池兜底）；
  若工具层未来提供原生 async handler，可进一步省掉线程池跳转。
- 路由层 await 已就位，流式输出（明日）可直接基于 async 链路扩展。
