# 长期记忆：MemoryStrategy 抽象 + BM25 乘法衰减召回（P1 ⑦）

## 背景

P0 ①③ 的 context 策略是纯窗口裁剪：裁掉的旧消息**直接抛弃**（`docs/context与记忆机制设计.md` 记录了这是"短期窗口与长期记忆的衔接缺口"）。⑦ 补上闭环：短期窗口裁掉的信息，经长期记忆仍可被召回。

架构对齐 Mitta（用户方案原话：BM25 检索 + 乘法衰减 + 插件化策略，见设计文档 §3.2/§4.2）。

## 设计

### 1. `src/agent/memory.py`

- **`MemoryEntry`**：一条长期记忆 = id/session_id/content/created_at/access_count（被召回次数，衰减依据）；
- **`MemoryStrategy`（ABC，插件化）**：`remember` 写 / `recall` 读（衰减后分数降序 top-k）/ `forget` 清会话——检索算法可换（BM25 / 未来向量 / 混合），runtime 只依赖抽象；
- **`BM25Memory`**：标准 Okapi BM25（k1=1.5, b=0.75）内存实现：
  - **切分**：无分词器折中——CJK 单字 + 英文/数字按词小写（`_tokenize`）；
  - **IDF/词频**：`log((N-df+0.5)/(df+0.5)+1)` × 词频饱和度公式，逐查询词累加；
  - **相关性过滤**：与 query 无共享词（分数 0）的记忆不召回，避免无关记忆塞进上下文；
  - **乘法衰减**：排序分 = BM25 分 × `decay_factor ^ access_count`（默认 0.9）。被反复召回的旧记忆分数打折，让新/未被充分利用的记忆有机会排前，防"记忆固化"（Mem0/Mitta 乘性衰减思路）；命中条目 `access_count += 1` 下次生效。

### 2. runtime 接入（`src/agent/runtime.py`）

- `AgentRuntime.__init__` 新增 `memory`（默认 None，不配即无记忆，既有测试零影响）+ `memory_recall_k=10`；
- **召回时机与放置方式**：`_build_messages` 以**本轮提问**为 query 召回 top-k（用户方案 10 条），拼入**本次请求的 system**（`【长期记忆（历史问答，仅供参考）】` 动态段）——不写回缓存的 `session.system_prompt`（静态 base 不受污染，每轮召回不同）；
- **落库时机**：每轮 QA 结束后 `remember(f"Q: {user_content}\nA: {reply}")`——QA 合并为一条记忆，短期窗口裁掉的信息可经召回重新进入上下文，形成闭环；
- main.py 装配 `BM25Memory`，删除会话时 `memory.forget` 防泄漏。

## 验证

- 新增 `tests/test_memory.py` 8 用例：切分、相关召回、无关过滤、乘法衰减换序（同分记忆 k=1 两次召回验证 0.9^1 让位）、会话隔离、forget、runtime QA 落库 + 下一轮召回进 system、未配置记忆零影响；
- 全量测试 **164 passed**（156 + 8），无回归。
