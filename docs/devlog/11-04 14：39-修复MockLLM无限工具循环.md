# 修复 MockLLM 无限工具循环

- **日期**：2026-11-04 14:39
- **关联功能**：Agent 运行时循环（AgentRuntime.run / MockLLM.generate）

## 问题现象

运行 `AgentRuntime.run(session, "帮我计算 1+2*3")` 时，工具调用后没有正常返回最终回复，而是**持续调用 calculator 直至单次问答轮次上限（8 轮）**，最终回复为"已达到单次问答工具调用轮次上限"，而非计算结果。对应测试 `test_tool_call_flow_calculator` 失败（期望 trace 长度为 1，实际为 8）。

## 根因

`MockLLM.generate()` 的路由逻辑是"在消息历史中取**最后一条 user 消息**判断是否调用工具"。工具执行后，运行时把工具结果以 `role="tool"` 消息追加进上下文并继续 loop，但 MockLLM 每一轮仍然命中同一条 user 消息（"帮我计算 1+2*3"），于是**每次生成都返回同一个工具调用**，形成无限循环。

真实 LLM 的行为是：拿到工具结果后，会结合结果**生成最终回复并停止调用工具**；Mock 实现没有模拟这一关键行为。

## 修复方案

在 `MockLLM.generate()` 开头增加判断：若消息历史最后一条是 `role="tool"`（说明上一轮刚执行完工具），则模拟 LLM 总结工具结果，直接返回最终回复（`content`），不再继续路由工具。

```python
last = messages[-1] if messages else {}
if last.get("role") == "tool":
    content = str(last.get("content", ""))
    return LLMResponse(content=f"好的，{content}", tool_calls=None)
```

## 验证

- 修复后重跑全部测试：**69 passed**（覆盖工具正常/异常/边界、路由、会话隔离、运行时循环与轮次限制）。
- 关键回归用例：工具调用流程 trace 长度 = 1、rounds_used = 1，回复为工具结果总结；轮次上限用例仍按预期工作。
