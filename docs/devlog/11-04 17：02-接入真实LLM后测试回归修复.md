# 修复：接入真实 LLM 后测试全红

## 现象

`pytest tests -q` 全量失败：

1. collection 阶段报 `ModuleNotFoundError: No module named 'dotenv'`，`tests/test_api.py` 与 `tests/test_runtime.py` 无法收集；
2. 补装依赖后，`test_rounds_used_counts_tool_calls_not_decision_rounds` 报
   `TypeError: Can't instantiate abstract class MultiToolLLM without an implementation for abstract method 'init'`。

## 根因

1. `requirements.txt` 新增 `python-dotenv` 但 venv 未安装；`src/agent/llm.py` 顶部 `from dotenv import load_dotenv` 使模块导入直接失败（测试与 Mock 路径一并挂掉）。
2. `src/main.py` 硬编码 `AgentRuntime(llm=DeepSeekLLM().init(), ...)`：`test_api.py` 发消息会走真实 DeepSeek API，依赖网络与真实 key，破坏测试的确定性与速度。
3. `LLMClient` 新增抽象方法 `init()` 后，测试辅助类 `MultiToolLLM`（tests/test_runtime.py）未实现该方法，实例化报 TypeError。

## 修复

1. 安装 `python-dotenv`（pip 临时目录隔离到 `.venv\pip-tmp`，根治根目录临时文件堆积）。
2. `src/main.py` 增加 `LLM_BACKEND` 环境变量切换：默认 `mock`（测试/演示稳定），`LLM_BACKEND=deepseek` 时走 `DeepSeekLLM().init()`。
3. `MultiToolLLM` 补 `init()` 空实现，满足抽象契约。

## 验证

- 后端：`92 passed`（原 87 + 新增 5：`SessionManager.remove` 2 项、删除接口 2 项、自动建默认会话 1 项）。
- 前端：`tsc --noEmit` 双配置 + `vite build` 全部通过。
- `api.json` 重新导出：OpenAPI 3.0.3，`paths=6`（新增 `DELETE /api/sessions/{session_id}`）。
