## 模块① 主循环：四步 + 继续/终止判断

### 需求描述
实现 Agent 基本循环，覆盖一次用户请求的完整流转。

### 关键机制（四步）
1. **Step one**：接收用户输入
2. **Step two**：判断是直接回复，还是调用工具（对 query 做路由）
3. **Step three**：调用工具（经工具注册表校验后执行）
4. **Step four**：根据工具结果判断——继续 loop，还是返回结果给用户

### 继续 / 终止判断
- **继续条件**：工具结果不足以生成最终答案，需要再次调用工具或继续推理。
- **终止条件**：
  - 已达到本轮最大工具调用轮次（见模块⑤，单次 QA 维度）；
  - 已获得最终答案（LLM 输出解析为 final answer）；
  - 无可用工具或工具调用失败且无法恢复。

### 边界与异常
- 空输入 / 无意义输入：应直接回复或提示，不触发工具调用。
- 工具调用异常：捕获后按模块⑥处理，避免循环卡死。
- 轮次归零：强制终止并返回已收集的部分结果 + 提示信息。

### 测试要点
- 四步流转顺序正确性；继续 / 终止分支全覆盖；空输入；工具失败后的终止路径。

## 模块② 工具注册

### 需求描述
提供统一的工具注册机制，Runtime 依据注册信息调用工具。

### 关键机制
- 注册表字段（每个工具至少包含）：
  - `name`：工具唯一名称
  - `description`：功能描述（供 LLM 判断是否调用）
  - `参数 Schema`：参数结构定义（类型、必填项、字段说明，JSON Schema 风格）
- **至少实现三个工具**：`calculator`、`search`（可 mock）、`read_docs` / `todo` / `weather`（可自定义）。
- 中后期可选：接入 MCP（接入方式参考 mitta 项目）。

### 边界与异常
- 参数校验：缺参、类型不符、非法值 → 返回结构化错误，不执行。
- 未注册工具 / 未知工具名：明确报错。
- 工具执行超时 / 异常：按模块⑥兜底。

### 测试要点
- 注册与发现；参数 Schema 校验（正常 / 缺失 / 类型错误 / 边界值）；未知工具调用；工具执行失败。

## 模块③ LLM 输出解析

### 需求描述
解析 LLM 输出，区分三种内容：**思考过程（reasoning）**、**工具调用（tool call）**、**最终答案（final answer）**。

### 关键机制
- 定义一种可解析的结构化输出约定（格式待定，见「待定项」：XML / JSON / 特殊标记之一）。
- 解析器将 LLM 输出切分为上述三类，供主循环路由（有 tool call → 进入 Step three；有 final answer → 终止返回）。
- 思考过程：可用于 trace / 日志展示（参考模块⑥）。

### 边界与异常
- **格式异常**：输出不符合约定（缺闭合标签、非法 JSON、截断）→ 兜底处理（重试 / 直接回复 / 报错），不静默吞掉。
- 同时出现 tool call 与 final answer：定义优先级（待定项）。
- 多次 tool call：支持一次输出多个工具调用（取决于格式约定，待定项）。

### 测试要点
- 三类内容正确解析；格式异常兜底；截断输出；混合输出（tool call + 思考过程）。

## 模块④ session 管理

### 需求描述
多窗口（多会话）独立、互不干扰、可续聊。

### 关键机制
- **短期记忆**：会话内上下文（消息历史）按 session 隔离存储。
- **会话隔离**：每个 session 独立状态，不跨会话串扰。
- **可续聊**：同一 session 可恢复历史上下文继续对话。
- 长期记忆：可效仿 mitta 使用的 mem0（一期是否实现见「待定项」）。

### 边界与异常
- 会话不存在 / 已过期：创建或返回明确提示。
- 并发写同一会话：保证状态一致性（锁或原子更新，机制待定项）。
- 会话存储落库失败：按模块⑥处理。

### 测试要点
- 多 session 互不干扰；续聊恢复历史；会话状态隔离；会话数据持久化与恢复。

## 模块⑤ context 管理

### 需求描述
对上下文做有效管理：轮次上限、状态记忆、追问、基础压缩。

### 关键机制
1. **最大轮次限制**：针对单次 QA 的工具调用轮次上限；**轮次采用单次会话维度，非全局**——否则会导致整个会话后续无工具次数分配。
2. **用户持续会话上下文管理**：短期记忆窗口；注意**上下文膨胀**（对应架构设计题模块一第二问）。
3. **追问支持**：带工具追问 + 纯会话追问；本质是对 query 判断是否需要工具调用，再进行路由（与模块① Step two 联动）。
4. **context 压缩（基础版）**：窗口截断 或 summary 节点，后续取舍（见「待定项」）。

### 边界与异常
- 轮次达到上限：本轮强制终止（模块①联动）。
- 窗口超限：触发压缩策略；压缩后需保持对话可续（对应架构题"压缩后对话仍流畅"）。
- 压缩内容丢失关键信息：需在压缩策略中考虑（保留关键事实 / 摘要质量）。

### 测试要点
- 轮次上限生效（单会话维度）；窗口超限触发压缩；压缩后追问仍可回答；压缩不丢关键状态。

## 模块⑥ 健壮性：异常处理 + 工具调用 trace / 日志

### 需求描述
基本异常兜底与可观测性。

### 关键机制
- **基本异常处理**（至少覆盖）：
  - 落库处理（存储失败）
  - 消息处理（非法消息 / 解析失败）
  - 网络处理（网络错误）
  - 连接超时处理
  - 格式异常处理（LLM 输出、工具参数等）
- **工具调用 trace**（参考 mitta）：为工具调用的执行参数和结果单独开一个展示区（div），包含工具名、请求参数等；用于调用链展示与排查。

### 边界与异常
- 异常类型分级：可重试 vs 不可重试；重试上限。
- trace 记录完整：工具名、请求参数、结果、耗时、错误（如有）。
- trace 数据量大时的裁剪 / 滚动策略（待定项）。

### 测试要点
- 各类异常触发与兜底路径；trace 内容完整性；重试行为。
