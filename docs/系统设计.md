## 2. 六大需求模块实现现状

### 模块① 主循环（`src/agent/runtime.py`）

四步最小循环：接收输入 → LLM 判断 → 工具调用 → 继续/终止。

**消息结构（OpenAI 兼容工具调用契约，commit `8f89e71` 确立、本版延续）：**
- LLM 决定调用工具时，先把「决策消息」写入历史：一条 `assistant` 消息，`tool_calls` 为 OpenAI 兼容形状的**纯 dict 列表**，每条含唯一 `id`（`ToolCall.id` 为空时用 `uuid` 兜底生成 `call_xxx`）；`arguments` 必须为 **JSON 字符串**（`json.dumps` 序列化）
- 逐条执行工具后，结果以 `tool` 消息回填，`tool_call_id` **必须与决策消息中的 id 同源**（"订单号"：API 靠它把结果挂到那一次调用上，`zip` 保证一一对应）
- assistant 决策/总结消息落库时携带 `reasoning` 字段（DeepSeek 的 `reasoning_content` / MockLLM 规则文案），前端刷新后按时间序穿插渲染

**异步主循环（commit `b5bd368` 引入双轨，commit `6cd2572` 收敛为单主循环）：**
- 唯一主循环是 `async_run()`（async，FastAPI 主路径）；`run()` 收敛为薄包装 `asyncio.run(self.async_run(...))`，仅供测试 / 脚本在同步上下文调用
- 工具 handler 全部为 async（`Tool.handler` 类型 `Callable[..., Awaitable[str]]`）：`async_run()` 内直接 `await self._execute_tool(...)`，不经线程池；search / weather 用 `httpx.AsyncClient` 发请求
- 记忆落库（`_remember_round`：同步 SQLite 写 + 同步 LLM 提取）仍用 `asyncio.to_thread(...)` 包装，不阻塞事件循环
- `main.py` 的 `POST /messages` 改为 async，走 `runtime.async_run`，完成后 `manager.save(s)` 落库
- 事件发布贯穿决策 / 执行 / 回复全流程（详见第 4 节）

**继续/终止判断细节（同前版）：**
- 终止条件：LLM 返回最终答案（无 tool_calls）、达到 `max_rounds`（默认 8）轮次上限
- 轮次上限兜底：循环耗尽后返回「已达到单次问答工具调用轮次上限」提示
- 会话忙保护：`session.state != "idle"` 时抛 `SessionBusyError`，API 层映射 HTTP 409（对应架构题模块四第 2 问的最小实现）；`async_run` 的 `finally` 复位 state=idle
- **rounds_used 口径**（commit `b6a9486`）：统计**最近一条 user 消息之后**实际执行的 tool 消息条数，历史会话中的工具调用不计入本次问答

### 模块② 工具注册（`src/agent/tools/`）

注册表机制不变（`Tool` = name + description + parameters(JSON Schema) + handler（async 函数，签名 `Callable[..., Awaitable[str]]`）；重复注册报错）。**工具 4 个：**

| 工具 | 实现 | 数据源 | 说明 |
|---|---|---|---|
| `calculator` | `calculator.py` | 本地计算 | **AST 白名单安全求值**（四则 + 取模 + 幂 + 括号 + 数字常量，空命名空间），杜绝 `eval` 注入；除零 / 语法 / 溢出均转错误消息 |
| `search` | `search.py` | **联网 DuckDuckGo**（HTML 版 + BeautifulSoup） | `_fetch()` 独立模块级函数便于测试 monkeypatch；网络/解析失败兜底返回错误文案；最多展示 5 条 标题+摘要 |
| `weather` | `weather.py` | **联网 wttr.in**（`?format=j1` 免费 API） | 解析当前天气：中文描述（`lang_zh`，缺失回退英文）、温度、湿度、风向/风速；网络/超时兜底 |
| `todo` | `todo.py` | 进程内内存表 | `action: add/list/done`（参数 Schema 含 enum）；add 校验内容非空、done 按编号或原文本匹配；未完成在前排序 |

- search / weather 为**真实联网查询**（commit `0a083cc`），无需 key；网络层独立为 `_fetch()`，测试用 monkeypatch 注入假响应，保持离线确定性
- todo 为内存存储（重启丢失），与 session 同为内存实现（commit `ecdaf37`）
- 注册表对外接口：`register()` / `get_tool()` / `get_all_tools()`（API 层 `/api/tools` 直接暴露 name/description/parameters）

### 模块③ LLM 输出解析（`src/agent/llm.py`）

**LLMClient 抽象**（`init()` + `generate()` + `async_generate()`），两种实现：

**DeepSeekLLM（真实接入，OpenAI-compatible）：**
- `init()`：延迟导入 `openai`，**同时创建 `OpenAI` 与 `AsyncOpenAI` 双客户端**（timeout=60）；key 缺失快速失败（ValueError）；`BASE_URL` 默认 `https://api.deepseek.com`、`MODEL_NAME` 默认 `deepseek-flash`
- 模块顶部 `load_dotenv()` 加载 `.env`，**不 override**（commit `b5bd368` 修正）：shell 环境变量优先，保证测试里 `$env:LLM_BACKEND=mock` 不被 `.env` 覆盖误走真实 LLM
- `generate()` / `async_generate()` 同构三步：① 内部消息历史 → OpenAI 格式（`user`/普通 `assistant` 透传；`assistant` 带 tool_calls 包成 `{id, type:"function", function:{name, arguments}}`；`tool` 消息带 `tool_call_id` 回显）；② 注册表 → `tools` 参数（`parameters` 直接复用项目 JSON Schema）；③ 响应解析——`tool_calls` 非空则 `json.loads(fn.arguments)` 还原参数字典（解析失败兜底空字典），否则取纯文本；两者均解析 `reasoning_content` 到 `LLMResponse.reasoning`
- 测试用伪造 client（monkeypatch）覆盖 纯文本 / 工具调用 / 异常 三类，不联网、不用真 key（`tests/test_deepseek_llm.py`）

**MockLLM（默认，规则式）：** 触发词路由 + 工具结果后总结回复（避免无限循环，devlog `11-04 14：39-修复MockLLM无限工具循环.md`）；`init()` 空实现满足契约；**记忆提取分支**（详见第 3 节）：system 含「长期记忆提取器」标记时走 `_extract_memories` 规则近似（含指代词补全、`{"facts":[...]}` 输出），该判断**必须先于工具路由**，防止提取请求被误路由。

**后端切换（commit `f81c62c`）：** `LLM_BACKEND` 环境变量，默认 `mock`；`LLM_BACKEND=deepseek` 时 `DeepSeekLLM().init()`。默认 mock 保证测试与演示稳定（详见 `docs/真实LLM接入改造路线.md` 与 devlog `11-04 17：02-接入真实LLM后测试回归修复.md`）。

### 模块④ session 管理（`src/agent/session.py`）

**存储抽象（commit `9783d84`）：**
- `SessionStore` 抽象接口（Repository 模式）：`create / get / list / remove / save`；调用方修改 `Session` 对象后显式 `save()` 落库，`get()` 从存储重建最新会话
- `Session` 字段：`session_id`（uuid hex）/ `created_at` / `messages` / `traces` / `state`（idle|busy）/ **`system_prompt`**（会话级 system prompt，首次运行时构造，之后复用；**不写入 session.messages**，对话历史保持干净，仅存文本字段）
- `SessionManager`：内存实现，对象即引用，`save()` 为 no-op（保持接口一致）；`append_trace` 直接扩展对象引用
- `SQLiteSessionStore`：**sessions / messages / traces 三表**（logs 表由中间件另用）；`get()` 从 DB 重建消息（`extra` 列 JSON 存 reasoning 等扩展字段）；`save()` 全量重建该会话 messages/traces + 会话行 upsert（标准 `UPDATE→INSERT` 两步，未来换 PG 仅换驱动）；`remove()` 级联删三表；`list()` 逐会话 get（本地开发规模，保证 message_count 与接口语义一致）

**两个基础设施函数（沙箱/Windows 根因修复）：**
- `connect_sqlite(db_path)`：**每次操作新连接**（避免跨线程共享，适配 FastAPI 线程池 + 事件循环并发）+ `PRAGMA journal_mode=MEMORY`——当前运行环境（沙箱）会拦截 SQLite 默认 rollback journal 文件（.db-journal）的落盘，导致 DDL/DML 静默失效；MEMORY 模式绕过拦截，数据库主文件本身仍正常持久化（实测验证；崩溃安全性略降，单机本地部署可接受）。详见 devlog `11-05 12：41-存储抽象与SQLite落库根因修复.md`
- `sqlite_transaction(db_path)`：短连接事务上下文，成功 commit / 异常 rollback / 最后必 close。注意 `with sqlite3.connect(...) as conn` 只提交**不关闭连接**，Windows 下文件句柄未释放导致后续无法删除数据库文件（实测 PermissionError）

**环境变量：** `SESSION_STORE`（默认 `memory`；`sqlite` 时用 `SESSION_DB`，默认 `data/agent-harness.db`，目录自动创建）；API 层 POST 消息后调 `manager.save(s)` 落库。

**API 层行为（同前版）：** 列表为空时惰性创建默认会话；删除会话额外清理该会话的事件队列与长期记忆（防内存泄漏）；会话不存在 → 404。

### 模块⑤ context 管理（`src/agent/context.py`，commit `46f4640`）

| 子项 | 状态 | 说明 |
|---|---|---|
| 轮次上限 | ✅ 已实现 | `max_rounds=8`，**单次会话维度非全局**（仅约束单次 QA 的工具调用次数，不消耗后续问答额度） |
| 状态记忆（短期窗口） | ✅ 已实现 | 完整消息历史随 session 累积，作为 LLM 输入上下文 |
| 追问路由 | ✅ 已实现 | `src/agent/router.py`：触发词表（calculator/search/weather/todo）；`extract_args()` 最小参数提取 |
| **基础压缩（窗口截断）** | ✅ **已实现（本版新增）** | `trim_messages()` 纯窗口截断（见下）；summary 摘要压缩未实现（待办，见第 9 节） |
| 长期记忆 | ✅ 已实现（⑦） | 见第 3 节 |

**context.py 三个纯函数（窗口截断半已落地，对应架构题模块一第二问）：**
- `build_system_prompt(tool_names, now)`：角色定位 + 可用工具 + 工具约定 + **当前时间（UTC ISO）**——真实 LLM 无内置时钟，不注入易读错时间；runtime 会话首次构造并缓存到 `session.system_prompt`，之后复用
- `estimate_tokens(text)`：`len//2` 粗算（中文≈1 字 1 token、英文≈4 字符 1 token，偏保守）
- `trim_messages(messages, max_tokens)`：**system 无条件保留** + 从最新往回保留 + **最后一条 user 消息无条件保留**；超窗从最旧丢；单条超长不截断（只裁剪列表，不拆消息）

**runtime `_build_messages()` 组装顺序：** 会话首次构造并缓存 `session.system_prompt` → 若配 memory，以**本轮提问**为 query BM25 召回 top-k 拼入本次 system 动态段（**不写回** session.system_prompt，静态 base 不被污染）→ 追加本轮 user → `trim_messages(messages, max_context_tokens=4000)`。写回 session.messages 时**过滤 role==system**（system 只存 session.system_prompt 字段）。

设计讨论稿（用户方案原话 + 基线 + 待办清单）见 `docs/context与记忆机制设计.md`（commit `880b0fd` 新建，可引用不重写）。

### 模块⑥ 健壮性

- **工具级异常兜底**（`_execute_tool`）：未知工具 / 参数不匹配（TypeError）/ 任意异常（Exception）→ 结构化 `status="error"` 错误结果，不阻断循环
- **工具执行超时**（`_execute_tool`，commit `4242e53`）：`asyncio.wait_for(handler(...), timeout=TOOL_TIMEOUT_SECONDS)`（默认 10s），卡死工具转「工具执行超时」error 结果回给 LLM；边界：`wait_for` 只能取消真 await 的工具，纯 CPU 的 calculator 靠自身输入校验兜底
- **记忆链路异常隔离**（commit `4242e53`）：记忆是弱一致性的附属功能——`_build_messages` 召回失败按无记忆处理，`_remember_round` 召回 / 提取 / 写入逐段降级（提取失败降级存原始 QA），`async_run` 外层再兜一层；**记忆落库排在回复推送、`session.messages` 回写与会话释放之后**：写回与 `state=idle` 先完成，记忆失败只影响记忆自身——前端收到 done 后追问不会被 `SessionBusyError` 拒掉（**会话何时可复用由对话决定，不由记忆决定**）；提取器所需的「最近消息」使用写回前的历史快照，避免把本轮回复重复计入上下文、挤掉真正的上文
- **联网工具网络兜底**：search / weather 网络失败、超时、解析失败一律返回错误文案（对应需求「异常处理：网络处理、连接超时」）
- **trace 记录**：每次工具调用记录 `tool` / `args` / `result` / `status` / `duration_ms`，随会话累积，独立 API 查询；真实 LLM 路径下同样记录每次实际工具调用
- **全局中间件**（commit `7f17085`，`src/main.py` 的 `@app.middleware("http")`）：
  - 请求计时（`time.perf_counter` → `duration_ms`）
  - **未捕获异常兜底**：捕获后返回 500 JSON，`detail` 仅含异常类型名，**不泄露堆栈**
  - HTTPException（404/409 等）由内层 ExceptionMiddleware 转响应，中间件只负责计时记录
  - `finally` 中写请求日志（`LogRecord`：ts / method / path / session_id（从路径解析）/ status / duration_ms / error），`LOG_STORE` 切换内存或 SQLite（logs 表，参数化 INSERT）
- **HTTP 层**：会话不存在 → 404；会话忙 → 409；删除会话 → 204；消息长度 1~2000 校验
- **前端 trace 展示**：`TracePanel` 独立面板 + **工具调用已内嵌进 AI 消息块**（`ToolCallCard`，详见第 6 节）

## 3. 长期记忆⑦（`src/agent/memory.py`，commit `f6c4304` / `0a036bc`）

**状态：已实现（内存 BM25 一期）。** 对齐 mem0/Mitta 写入管线（`MemoryStrategy` 抽象插件化，未来可换 SQLite/向量实现）。

**数据结构与检索（`BM25Memory`）：**
- `MemoryEntry`：id / session_id / content / created_at / access_count
- Okapi BM25：`k1=1.5`、`b=0.75`；**切分**：CJK 单字 + 英文按词（`[a-z0-9]+`），无分词器保守折中
- IDF 对数平滑；**乘法衰减** `decay_factor ** access_count`（默认 `decay_factor=0.9`）——访问越多的记忆分数越低，抑制热门记忆长期霸榜
- `recall(query, top_k)` 只返回分数 > 0 的条目，命中条目的 `access_count + 1`
- **md5 去重**：按内容 md5 判重，防止重复事实重复入库

**落库层 LLM 提取（`MemoryExtractor`，对齐 mem0 写入管线）：**
- `EXTRACTOR_SYSTEM_PROMPT`：角色定义为「长期记忆提取器」，要求输出自包含事实（可独立理解）、与原文同语言、稳定可复用、不重复已有记忆，**只输出 JSON `{"facts":[...]}`**
- `build_extract_prompt` 三段：**Existing Memories（已有记忆）→ Last k Messages（最近消息，默认 10 条）→ New Messages（本轮问答）**；指代（如"那南昌呢"承接上文）在提取阶段由最近消息消解
- 解析容错：剥 ```json 围栏后解析；解析失败 / 空结果降级为**原始 QA 单条**（fallback），不丢失信息；**LLM 调用本身失败（网络 / 超时）同样降级为原始 QA**（commit `4242e53`，由 runtime 的 `_remember_round` 兜住）
- MockLLM 内置 `_extract_memories` 规则近似分支（system 含「长期记忆提取器」标记即触发，先于工具路由）；DeepSeek 走真实提取

**runtime 读写时机（README 提交物，重点）：**
- **召回时机**：每轮提问时，以 `user_content` 为 query BM25 召回 `top-k=10`（runtime 参数 `memory_recall_k=10`），拼入本次 system 动态段后交给 LLM
- **放置方式**：当前内存实现（BM25 条目列表），放置在 system 之后、以「【长期记忆（历史问答，仅供参考）】」段拼入本次请求上下文；**不写回** `session.system_prompt`，静态 base 不被污染
- **落库时机**：每轮 QA 完成后 `_remember_round`——先 recall 已有 top-5 供判重，再取最近 recent_k 条历史进提取上下文，LLM 提取出自包含事实、md5 去重后逐条 `remember()`

**接线（`src/main.py`）：** `memory = BM25Memory()` + `memory_extractor = MemoryExtractor(llm)` → `AgentRuntime(queue=event_queue, memory=memory, memory_extractor=memory_extractor)`；DELETE 会话时 `memory.forget(session_id)` 同步清理（防内存泄漏）。Mock 与 DeepSeek 后端复用同一套记忆管线。

## 4. 流式事件（`src/agent/events.py`，commit `cbaca04` 起）

**事件协议 4 类：**

| 类型 | 字段 | 说明 |
|---|---|---|
| `reasoning` | content | 思考过程，逐段发布 |
| `tool_call` | id / name / args | 工具调用开始（id 与决策消息 tool_calls 同源） |
| `tool_result` | id / result / status / duration_ms | 按 id 与 tool_call 配对 |
| `message_delta` | delta / done | 最终回复增量（`_publish_reply` 按 24 字符切块模拟流式，末块 `done`） |

**队列实现（`InMemoryQueue`）：** 会话隔离 deque（`max_per_session=500`，防无限膨胀）+ **单调 seq** + 锁保护；`subscribe(session_id, since)` 返回 `seq > since` 的增量；`latest_seq` 供锚点。

**轮询协议（`GET /api/sessions/{id}/events?since=N`）：** 返回 `events` + `latest_seq`；校验会话存在（404 语义一致）。前端 1s 级 `setInterval` 增量消费；断连后先刷新 `/messages` 全量，再以 `since=最新 seq` 续拉增量（`a00bae0` 完善锚点，避免历史事件灌入新消息块）。

## 10. 边界与限制（诚实清单）

- 会话 / trace 默认内存存储，进程重启丢失；SQLite 模式持久化（`SESSION_STORE=sqlite`），但 `journal_mode=MEMORY` 使崩溃安全性略降（最后未同步事务可能丢失）
- 长期记忆当前为**内存 BM25 实现**，进程重启丢失；未来换 SQLite / 向量库（`MemoryStrategy` 已抽象）
- 事件队列为内存实现，每会话最多保留最近 500 条（`max_per_session=500`），且**非持久化**——断连后的历史事件不回放，前端靠 `/messages` 全量刷新兜底
- MockLLM 为规则式：触发词路由精度有限（多工具同时命中取先注册者）、无真实语义理解；记忆提取为规则近似（CJK 单字切分无分词器，跨语言 / 长句事实提取精度受限）
- search / weather 依赖外网可用性（DuckDuckGo / wttr.in），离线或反爬时返回兜底错误文案
- 工具超时是 Agent 层兜底（`TOOL_TIMEOUT_SECONDS=10s`），但 `wait_for` 只能取消真 await 的工具：`calculator` 是包在 `async def` 里的纯 CPU 计算，超时无法中断，依赖自身输入校验与 AST 白名单
- 真实 LLM（DeepSeek）依赖 `.env` 密钥与网络，默认关闭；模型名须与服务器支持名完全一致（踩坑见 `docs/真实LLM接入改造路线.md`）
- **测试运行前提**：`.env` 配置了 `SESSION_STORE=sqlite` / `LLM_BACKEND=deepseek` 时，直接跑 pytest 会致部分用例失败（存储/LLM 行为与测试预期不符）；需以 `LLM_BACKEND=mock`、`SESSION_STORE=memory`、`LOG_STORE=memory` 覆盖运行（175 passed 实测）
- summary 摘要压缩未实现，超长会话仍会膨胀（对应架构题模块一第二问，窗口截断已实现）
- `trim_messages` 单条超长不截断（只裁列表不拆消息），极端超长单条会突破上下文预算
