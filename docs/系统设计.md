## 2. 六大需求模块实现现状

### 模块① 主循环（`src/agent/runtime.py`）

四步最小循环：
1. **接收用户输入**：`run(session, user_content)`，追加 user 消息
2. **判断直接回复 or 调用工具**：`llm.generate(messages)` 返回 `tool_calls` 或 `content`
3. **调用工具**：`_execute_tool()`，经注册表解析 + 参数绑定 + 异常兜底 + 耗时记录
4. **继续 / 终止**：有 `tool_calls` → 结果回填上下文后 `continue`；无 → 取 `content` 作为最终回复 `break`

**继续/终止判断细节：**
- 终止条件：LLM 返回最终答案（无 tool_calls）、达到 `max_rounds`（默认 8）轮次上限
- 轮次上限兜底：循环耗尽后返回「已达到单次问答工具调用轮次上限」提示
- 会话忙保护：`session.state != "idle"` 时抛 `SessionBusyError`，API 层映射 HTTP 409（对应架构题模块四第 2 问的最小实现）
- **rounds_used 口径**（commit `b6a9486`）：统计**最近一条 user 消息之后**实际执行的 tool 消息条数，历史会话中的工具调用不计入本次问答

### 模块② 工具注册（`src/agent/tools/`）

`Tool` 数据类 = `name` + `description` + `parameters`（JSON Schema）+ `handler`；全局注册表 `TOOL_REGISTRY`，重复注册报错。

| 工具 | 实现 | 参数 Schema | 说明 |
|---|---|---|---|
| `calculator` | `calculator.py` | `expression`（必填） | **AST 白名单安全求值**（仅允许四则 + 取模 + 幂 + 括号 + 数字常量，空命名空间），杜绝 `eval` 注入；除零 / 语法 / 溢出均转错误消息 |
| `search` | `search.py` | `query`（必填） | mock：内置知识库（agent/rag/mitta/langgraph/mem0/python/fastapi/context）关键词检索 |
| `weather` | `weather.py` | `city`（必填） | mock：预设 7 城市天气（北京/上海/广州/深圳/杭州/南昌/赣州） |

注册表对外接口：`register()` / `get_tool()` / `get_all_tools()`（API 层 `/api/tools` 直接暴露 name/description/parameters）。

### 模块③ LLM 输出解析（`src/agent/llm.py`）

- `LLMClient`（抽象基类）：`generate(messages) -> LLMResponse`，是 Agent 与大模型的**唯一交互点**
- `LLMResponse`：`content`（最终答案）或 `tool_calls`（工具调用列表）
- `MockLLM`（规则式）：命中工具触发词 → 返回 `ToolCall(name, args)`；否则返回规则文本回复
  - 工具刚执行完（末条消息 role=tool）→ 基于工具结果生成最终回复，**避免无限工具循环**（devlog：`docs/devlog/11-04 14：39-修复MockLLM无限工具循环.md`）
- 真实 API 接入点即 `LLMClient.generate()`；参考示例见 `src/init.py`（DeepSeek OpenAI-compatible 调用）

### 模块④ session 管理（`src/agent/session.py`）

- `Session`：`session_id`（uuid hex）/ `created_at` / `messages` / `traces` / `state`（idle|busy）
- `SessionManager`：内存仓库，`create / get / list / append_trace`；按创建时间倒序列表
- 会话隔离：不同 session 独立消息与 trace，互不干扰；同一 session 消息持续累积，支持续聊
- 存储为内存实现：进程重启即丢失，落库（PostgreSQL）留待中间件启用

### 模块⑤ context 管理

| 子项 | 状态 | 说明 |
|---|---|---|
| 轮次上限 | ✅ 已实现 | `max_rounds=8`，**单次会话维度非全局**（仅约束单次 QA 的工具调用次数，不消耗后续问答额度） |
| 状态记忆（短期窗口） | ✅ 已实现 | 完整消息历史随 session 累积，作为 LLM 输入上下文 |
| 追问路由 | ✅ 已实现 | `src/agent/router.py`：工具触发词表（calculator/search/weather），`route()` 判断是否需要工具调用；`extract_args()` 做最小参数提取（计算表达式 / 搜索词 / 城市名） |
| 基础压缩 | ⏳ 未实现 | 窗口截断 / summary 节点未落地（需求待定项，对应架构题模块一第二问） |
| 长期记忆 | ⏳ 未实现 | 规划参考 mem0，见第 7 节「memory 召回时机与放置方式」 |

### 模块⑥ 健壮性

- **工具级异常兜底**（`_execute_tool`）：未知工具 / 参数不匹配（TypeError）/ 任意异常（Exception）→ 结构化 `status="error"` 错误结果，不阻断循环
- **trace 记录**：每次工具调用记录 `tool` / `args` / `result` / `status` / `duration_ms`，随会话累积，独立 API 查询
- **HTTP 层**：会话不存在 → 404；会话忙 → 409；消息长度 1~2000 校验
- **trace 展示**：前端 `TracePanel` 以独立 div 渲染（工具名 / 状态 / 耗时 / 参数 / 结果），后续规划嵌入 AI 消息流（见第 7 节）

## 3. API 契约（OpenAPI 3.0.3）

后端自动生成契约，导出脚本 `scripts/export_api.py` → 根目录 `api.json`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| POST | `/api/sessions` | 创建会话（201） |
| GET | `/api/sessions` | 会话列表 |
| GET | `/api/sessions/{id}/messages` | 会话历史消息 |
| POST | `/api/sessions/{id}/messages` | 发送消息（body: `content` 1~2000 字），返回 `reply` / `trace` / `rounds_used` / `max_rounds` |
| GET | `/api/tools` | 工具注册表（name / description / parameters） |
| GET | `/api/sessions/{id}/trace` | 会话工具调用 trace |

## 4. 前端（Vite + React + TS）

- 布局（`App.tsx`）：左侧 `SessionList`（会话列表 / 新建）+ 右侧 `ChatBox`（消息流 + 输入框）+ `TracePanel`（独立 trace 面板）+ 错误栏
- API 封装（`api.ts`）：相对路径 `/api`，dev 模式由 Vite proxy 转发到 `http://127.0.0.1:8000`，无跨域问题
- 类型（`types.ts`）：与后端契约对应的 `SessionInfo / ChatMessage / TraceItem / ChatResult`
- 组件：`ChatBox`（消息渲染 + 发送，busy 态禁用）、`SessionList`（会话切换）、`TracePanel`（trace 独立 div）
- 构建：`npm run build` = `tsc --noEmit`（类型检查）+ `vite build`（commit `ed3854d` 起构建产物治理）

## 6. 环境与工程

- 后端环境：`setup.ps1` 一键创建/复用 `.venv` 并安装 `requirements.txt`（fastapi / uvicorn / pytest / httpx，Python 3.13）；同时把 pip 临时目录固定到 `.venv\pip-tmp`，避免临时文件散落项目根
- 后端启动：`python src/main.py`，默认端口 8000（`PORT` 环境变量可覆盖）；Windows 端口保留段（7449-8248）报 WinError 10013 时换端口（如 `$env:PORT=18000`）
- 前端启动：`cd frontend && npm install && npm run dev`（5173 端口，proxy 指向 8000）
- devlog 规范：`docs/devlog/`，命名 `MM-DD HH：mm-具体解决的问题.md`（时间冒号全角），记录现象 / 根因 / 修复 / 验证

## 8. 边界与限制（诚实清单）

- 会话 / trace 为内存存储，进程重启丢失；落库待中间件启用
- MockLLM 为规则式：触发词路由精度有限（如多工具同时命中取先注册者）、无真实语义理解
- 工具数据为固定 mock（calculator 可真实计算；search / weather 为预设数据）
- 基础 context 压缩未实现，长会话仍会膨胀（对应架构题模块一第二问的待解决项）
- 真实大模型 API、异步工具、跨进程持久化均未实现
