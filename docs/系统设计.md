## 2. 六大需求模块实现现状

### 模块① 主循环（`src/agent/runtime.py`）

四步最小循环：接收输入 → LLM 判断 → 工具调用 → 继续/终止。

**消息结构扩展（commit `8f89e71`，为真实 LLM 接入而改）：**
- LLM 决定调用工具时，先把「决策消息」写入历史：一条 `assistant` 消息，`tool_calls` 为 OpenAI 兼容形状的**纯 dict 列表**，每条含唯一 `id`（`ToolCall.id` 为空时用 `uuid` 兜底生成 `call_xxx`）；`arguments` 必须为 **JSON 字符串**（`json.dumps` 序列化）
- 逐条执行工具后，结果以 `tool` 消息回填，`tool_call_id` **必须与决策消息中的 id 同源**（"订单号"：API 靠它把结果挂到那一次调用上，`zip` 保证一一对应）

**继续/终止判断细节（同前版）：**
- 终止条件：LLM 返回最终答案（无 tool_calls）、达到 `max_rounds`（默认 8）轮次上限
- 轮次上限兜底：循环耗尽后返回「已达到单次问答工具调用轮次上限」提示
- 会话忙保护：`session.state != "idle"` 时抛 `SessionBusyError`，API 层映射 HTTP 409（对应架构题模块四第 2 问的最小实现）
- **rounds_used 口径**（commit `b6a9486`）：统计**最近一条 user 消息之后**实际执行的 tool 消息条数，历史会话中的工具调用不计入本次问答

### 模块② 工具注册（`src/agent/tools/`）

注册表机制不变（`Tool` = name + description + parameters(JSON Schema) + handler；重复注册报错）。**工具已扩展为 4 个：**

| 工具 | 实现 | 数据源 | 说明 |
|---|---|---|---|
| `calculator` | `calculator.py` | 本地计算 | **AST 白名单安全求值**（四则 + 取模 + 幂 + 括号 + 数字常量，空命名空间），杜绝 `eval` 注入；除零 / 语法 / 溢出均转错误消息 |
| `search` | `search.py` | **联网 DuckDuckGo**（HTML 版 + BeautifulSoup） | `_fetch()` 独立模块级函数便于测试 monkeypatch；网络/解析失败兜底返回错误文案；最多展示 5 条 标题+摘要 |
| `weather` | `weather.py` | **联网 wttr.in**（`?format=j1` 免费 API） | 解析当前天气：中文描述（`lang_zh`，缺失回退英文）、温度、湿度、风向/风速；网络/超时兜底 |
| `todo` | `todo.py` | 进程内内存表 | `action: add/list/done`（参数 Schema 含 enum）；add 校验内容非空、done 按编号或原文本匹配；未完成在前排序 |

- search / weather 由固定 mock 升级为**真实联网查询**（commit `0a083cc`），无需 key；网络层独立为 `_fetch()`，测试用 monkeypatch 注入假响应，保持离线确定性
- todo 为内存存储（重启丢失），与 session 同为内存实现（commit `ecdaf37`）
- 注册表对外接口：`register()` / `get_tool()` / `get_all_tools()`（API 层 `/api/tools` 直接暴露 name/description/parameters）

### 模块③ LLM 输出解析（`src/agent/llm.py`）

**LLMClient 抽象**（`init()` + `generate()`），两种实现：

**DeepSeekLLM（真实接入，OpenAI-compatible）：**
- `init()`：延迟导入 `openai`，环境变量兜底（`DEEPSEEK_API_KEY` / `BASE_URL` / `MODEL_NAME`，模块顶部 `load_dotenv(override=True)` 加载 `.env`）；key 缺失快速失败
- `generate()` 三步：① 内部消息历史 → OpenAI 格式（`user`/普通 `assistant` 透传；`assistant` 带 tool_calls 包成 `{id, type:"function", function:{name, arguments}}`；`tool` 消息带 `tool_call_id` 回显）；② 注册表 → `tools` 参数（`parameters` 直接复用项目 JSON Schema）；③ 响应解析——`tool_calls` 非空则 `json.loads(fn.arguments)` 还原参数字典（解析失败兜底空字典），否则取纯文本
- 测试用伪造 client（monkeypatch）覆盖 纯文本 / 工具调用 / 异常 三类，不联网、不用真 key（`tests/test_deepseek_llm.py`）

**MockLLM（默认，规则式）：** 触发词路由 + 工具结果后总结回复（避免无限循环，devlog `11-04 14：39-修复MockLLM无限工具循环.md`）；`init()` 空实现满足契约。

**后端切换（commit `f81c62c`）：** `LLM_BACKEND` 环境变量，默认 `mock`；`LLM_BACKEND=deepseek` 时 `DeepSeekLLM().init()`。默认 mock 保证测试与演示稳定（详见 `docs/真实LLM接入改造路线.md` 与 devlog `11-04 17：02-接入真实LLM后测试回归修复.md`）。

### 模块④ session 管理（`src/agent/session.py`）

- `Session`：`session_id`（uuid hex）/ `created_at` / `messages` / `traces` / `state`（idle|busy）
- `SessionManager`：内存仓库，`create / get / list / append_trace` + **新增 `remove()`**（删除会话，不存在抛 `SessionNotFoundError` → HTTP 404）；按创建时间倒序列表
- **API 层自动建会话**（commit `f81c62c`）：`GET /api/sessions` 列表为空时惰性创建一个默认会话，前端打开即有一个可用会话
- 会话隔离、可续聊不变；存储为内存实现，落库（PostgreSQL）留待中间件启用

### 模块⑤ context 管理

| 子项 | 状态 | 说明 |
|---|---|---|
| 轮次上限 | ✅ 已实现 | `max_rounds=8`，**单次会话维度非全局**（仅约束单次 QA 的工具调用次数，不消耗后续问答额度） |
| 状态记忆（短期窗口） | ✅ 已实现 | 完整消息历史随 session 累积，作为 LLM 输入上下文 |
| 追问路由 | ✅ 已实现 | `src/agent/router.py`：触发词表（calculator/search/weather/**todo**）；`extract_args()` 做最小参数提取（计算表达式 / 搜索词 / 城市名 / 待办动作） |
| 基础压缩 | ⏳ 未实现 | 窗口截断 / summary 节点未落地（需求待定项，对应架构题模块一第二问） |
| 长期记忆 | ⏳ 未实现 | 规划参考 mem0，见第 7 节「memory 召回时机与放置方式」 |

### 模块⑥ 健壮性

- **工具级异常兜底**（`_execute_tool`）：未知工具 / 参数不匹配（TypeError）/ 任意异常（Exception）→ 结构化 `status="error"` 错误结果，不阻断循环
- **联网工具网络兜底**：search / weather 网络失败、超时、解析失败一律返回错误文案（对应需求「异常处理：网络处理、连接超时」）
- **trace 记录**：每次工具调用记录 `tool` / `args` / `result` / `status` / `duration_ms`，随会话累积，独立 API 查询；真实 LLM 路径下同样记录每次实际工具调用
- **HTTP 层**：会话不存在 → 404；会话忙 → 409；删除会话 → 204；消息长度 1~2000 校验
- **trace 展示**：前端 `TracePanel` 以独立 div 渲染（工具名 / 状态 / 耗时 / 参数 / 结果），后续规划嵌入 AI 消息流（见第 7 节）

契约自动生成（`scripts/export_api.py` → `api.json`，当前 `paths=6`）。

| 方法 | 路径 | 说明 |

| GET | `/api/sessions/{id}/trace` | 会话工具调用 trace |

## 4. 前端（Vite + React + TS）

- 布局（`App.tsx`）：左侧 `SessionList`（会话列表 / 新建 / **删除**）+ 右侧 `ChatBox`（消息流 + 输入框）+ `TracePanel`（独立 trace 面板）+ 错误栏
- **会话管理增强**（commit `dea5c2e`）：删除按钮（`×`，`api.deleteSession` + 清除本地缓存）；自动选中第一个会话（配合后端惰性建会话，打开即用）
- **localStorage 缓存兜底**（`storage.ts`，commit `af022fa`）：消息与 trace 按会话隔离缓存（`agent-harness:msg:{sid}` / `agent-harness:trace:{sid}`）；选中会话先渲染缓存再以后端为准刷新；后端重启/刷新页面历史不丢
- **失效会话自动新建**：发送或加载时若后端 404（服务重启导致会话丢失），自动 `createSession` 并提示，不阻塞使用
- **消息布局**：用户消息与 AI 消息左右分列（`styles.css`，commit `dea5c2e` / `bcefac4`）
- API 封装（`api.ts`）：新增 `deleteSession`；`request()` 支持 204 空响应；dev 模式 Vite proxy 转发 `/api` → `http://127.0.0.1:8000`
- 构建：`npm run build` = `tsc --noEmit` 双配置 + `vite build`

- 契约导出：`.venv/Scripts/python.exe scripts/export_api.py` → `api.json`

## 8. 边界与限制（诚实清单）

- 会话 / trace / todo 均为内存存储，进程重启丢失；落库待中间件启用
- MockLLM 为规则式：触发词路由精度有限（多工具同时命中取先注册者）、无真实语义理解
- search / weather 依赖外网可用性（DuckDuckGo / wttr.in），离线或反爬时返回兜底错误文案
- 真实 LLM（DeepSeek）依赖 `.env` 密钥与网络，默认关闭；模型名须与服务器支持名完全一致（踩坑见 `docs/真实LLM接入改造路线.md`）
- 基础 context 压缩未实现，长会话仍会膨胀（对应架构题模块一第二问）
- 异步工具、跨进程持久化、中间件均未实现
