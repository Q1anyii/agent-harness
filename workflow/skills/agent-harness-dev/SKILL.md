# agent-harness 开发 Agent

## 启动（硬性第一步，不可跳过）

每次调用本 skill，**第一步必须完整读取**：

```
E:\工作文件\agent-harness\agent-harness\workflow\DEV_WORKFLOW.md
```

该文件是本工作流的**权威定义**（全局纪律、七步流程、提交与 devlog 规范）。本文件仅作速查；两者冲突时，以 DEV_WORKFLOW.md 为准。

## 项目上下文

- 项目根目录：`E:\工作文件\agent-harness\agent-harness`
- 需求输入：`docs/需求分析.md`（功能清单、测试要求、提交物清单）
- 架构参考：`docs/架构设计题.md`（架构取舍时对照）
- devlog 目录：`docs/devlog/`，命名 `MM-DD HH：mm-具体解决的问题.md`（时间冒号用全角 `：`）
- README 与功能详解文档：由文档撰写 Agent 维护（DOCS_WORKFLOW.md），开发 Agent 不负责

## 工作流速查（详细规则见 DEV_WORKFLOW.md）

1. **需求探查与澄清**：读全需求文档与用户指令；关键歧义先提问澄清，不猜测；需求/设计需深度打磨时，引导用户运行 `/grilling`（grill-me）。
2. **实现设计**：拆解功能点，每个功能明确四类边界——正常路径、异常路径、边界值、业务特殊场景；只改被点名范围。
3. **实现功能**：小步实现，一个功能一个独立可提交单元；写入安全实现（防注入、防越权、超时与异常兜底）。
4. **边界分析与功能测试（核心）**：每实现一个功能**立即生成对应功能测试**，用例覆盖多方位；运行测试，**全部通过后才允许提交**。
5. **验证**：用与生成路径不同的方式回读/运行；对照需求逐项自查。
6. **版本管理与提交**：每个功能一个独立提交，信息格式 `<功能名>：<一句话摘要>`；只 `git commit` 不 `push`；用 `git commit <文件路径>` 限定范围，不混入无关暂存改动。
7. **devlog**：每次重要 Bug 修复后撰写 devlog（现象、根因、修复、验证）。

## 全局纪律

- Git 先提交不推送，是否推送由用户决定。
- 审查：任务结束前先自审一遍再交付。
- 日志：重要 Bug 修复后必写 devlog。
- 严谨：绝不伪造内容；知识盲区明确说不，或先检索权威来源补全。
